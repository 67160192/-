สถานการณ์: ร้านเบเกอรี่แห่งหนึ่งต้องการระบบสั่งซื้อและตัดสต็อกวัตถุดิบ พนักงานหลายสาขาใช้ระบบพร้อมกัน และเจ้าของร้านต้องการดูรายงานยอดขายรายเดือนของแต่ละสาขา

จงตอบคำถามต่อไปนี้

  1. เลือก diagram อย่างน้อย 2 ชนิดที่เหมาะกับระบบนี้ พร้อมเหตุผล
  2. ระบุความเสี่ยงด้านความปลอดภัยและการทำงานพร้อมกันอย่างน้อย 2 จุด และเสนอด่านป้องกันสำหรับแต่ละจุด
  3. ออกแบบ test case อย่างน้อย 3 กรณี พร้อมระบุแหล่งที่มาของแต่ละกรณี
  4. ออกแบบ usability task หนึ่งข้อ โดยเขียนเป็นเป้าหมาย และระบุ severity ของปัญหาที่อาจพบ
ดูแนวคำตอบ (กรอบการให้คะแนน)
  1. Sequence Diagram สำหรับ flow การสั่งซื้อและตัดสต็อก และ Deployment หรือ Architecture Diagram สำหรับระบบหลายสาขา
  2. Race condition เมื่อหลายสาขาตัดสต็อกพร้อมกัน ด่านคือ transaction ร่วมกับ SELECT ... FOR UPDATE / IDOR เมื่อสาขาหนึ่งแก้ข้อมูลของอีกสาขา ด่านคือตรวจ branch_id ใน WHERE ทุก query / รับราคาจาก client ด่านคือดึงราคาจาก server
  3. เช่น ตัดสต็อกพอดี, สั่งเมื่อสต็อกไม่พอ (alt), สั่งพร้อมกันสองสาขา (race), รายงานยอดขายแยกตาม branch_id
  4. เขียน task เป็นเป้าหมาย เช่น "สั่งเมนูและยืนยันออเดอร์" ไม่ชี้นำปุ่มที่ต้องกด และระบุ severity เช่น Critical หากทำ task ไม่สำเร็จ
